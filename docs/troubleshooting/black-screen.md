# 黑屏、503 与显示异常

“503”或“黑屏”描述的是结果，不能仅凭它判断一定是独显、虚拟屏或编码器的问题。先保留原始报错与时间，再从最简单的画面路径开始。

## 先连接 Desktop

1. 客户端使用 1080p / 60 FPS、10 Mbps、SDR 和自动或 H.264。
2. 暂时关闭帧生成、额外画面增强和特殊捕获选项。
3. 在服务端确认目标显示器存在且已启用，再连接 Desktop。

Desktop 正常但游戏黑屏时，检查游戏是否本地正常启动、窗口／显示器是否选对，以及应用运行身份。先看[应用配置](../server/apps.md)，不要反复修改配对。

## 503 或启动失败

在 Sunshine 运行状态和日志中检查该次启动最早出现的错误：

| 日志或现象指向 | 下一步 |
| --- | --- |
| 目标屏幕不存在、无法启用 | 检查物理屏或虚拟屏、显示策略 |
| 捕获初始化失败 | 回到默认捕获，核对目标 GPU 与运行模式 |
| 编码器不可用 | 确认驱动、硬件编码能力，退回自动／H.264 |
| 应用启动错误 | 核对主程序、工作目录与启动器 |

**版本相关案例：**2026.1011 发行说明记录 NVIDIA `616.55`、`616.64` 驱动可能使虚拟屏无法激活并出现 503。若你恰好在这些版本上复现，先对照[该发行说明](https://github.com/AlkaidLab/foundation-sunshine/releases/tag/v2026.1011.150654.%E6%9D%82%E9%B1%BC)与后续修复信息选择兼容驱动；不要把这个案例套用于所有 503。

## 虚拟屏与退出恢复

在桌面 GUI 的基地显示器设置检查 ZakoDisplay 状态。按会话创建的屏幕可能只在连接时出现，未连接时不常驻不等于驱动失效。

先尝试保留物理屏的扩展策略，确认虚拟屏能出画，再测试仅使用虚拟屏。若提示重启，完成重启后重新检查。通过桌面 GUI 检查 ZakoDisplay 组件状态和显示设置。

退出后物理屏未恢复时：

1. 确认是否还有其他串流会话。
2. 检查当前显示策略，查看 Windows 显示设置。
3. 保存异常时段日志，再使用当前 GUI 提供的恢复／故障排除入口。
4. 需要修复驱动时，先保留配置和本地恢复方式。

具体策略见[虚拟显示器指南](../server/display.md)。

## 笔记本与混合显卡

记录核显、独显、驱动版本和目标显示器由哪块 GPU 驱动。捕获设备、虚拟屏渲染 GPU 与编码器的组合可能影响结果。

先用默认捕获和可工作的物理屏作对照，再一次调整一个选项。不要把拔掉全部屏幕、强制独显直连或修改 GPU 优先级当作所有笔记本的必做步骤。

## 有声音但画面冻结

检查主机本地画面是否也冻结；再看服务端捕获／编码日志和客户端解码统计。若提高画质或启用增强后才出现，先恢复之前的稳定配置。画面能出但持续掉帧时继续看[性能排查](./performance.md)。

## HDR 发灰、过曝或偏色

关闭 HDR 后若 SDR 正常，按[HDR 配置](../server/video.md#开启-hdr)核对主机输出、实际编码、客户端格式和屏幕模式。确认目标屏幕和配对设备没有套用另一台设备的亮度或校准配置。

不要用“服务端显示 Dolby Vision 已开启”代替终端原生显示验证。记录客户端实际格式与回退提示；只在某台设备复现时，把该设备型号与系统版本一并反馈。

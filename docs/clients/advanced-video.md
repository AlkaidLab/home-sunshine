# PyroWave 与客户端帧生成

本页以 **Android V+ 12.13.0** 为基线，两条路径都在普通串流稳定后单独测试。它们不代表所有 Moonlight 平台的相同能力，先查[平台支持导航](../getting-started/features.md)。

## PyroWave Vulkan 路径 {#pyrowave}

### 先检查条件

1. 保留一套已验证的 H.264／HEVC 或 AV1、SDR 配置，并记录画面与性能统计。
2. 在 Android 设置中打开 **PyroWave 能力检测**，检查 Vulkan、GPU 呈现模块和当前运行库的要求，保存报告。
3. 能力报告只检查驱动声明，不保证目标窗口、分辨率、HDR 呈现和性能都能工作。该版 GPU 呈现与 SDR 备用路径的 Vulkan 要求也不同，不能只看“支持 Vulkan”就通过判断。
4. 确认主机具备 PyroWave 编码支持和匹配运行组件；这是与客户端 Vulkan 解码配合的路径，不是普通 H.264 的显示滤镜。

### 开启、验证与回退

1. 在客户端视频编解码器设置选择标为实验性的 **PyroWave**，先关闭 HDR 和帧生成，保持原来的基础分辨率／帧率。
2. 重新连接 Desktop，查看实际协商格式。出现“PyroWave 协商失败，已回退”时，记录实际使用的编码，不能按 PyroWave 已成功评价性能。
3. 用持续运动场景观察解码、渲染和丢帧，再比较相同设置下的普通路径。普通 SDR 正常后，才单独验证该版本允许的 HDR 呈现。
4. 黑屏、异常颜色或性能下降时，恢复之前的视频格式，重连确认普通路径恢复，再提供能力报告与双方日志。

**12.13.0 明确不支持 PyroWave 的 HDR10+／Dolby Vision 动态元数据，也不支持该路径下的帧生成。** 需要这些能力时分别选择有明确支持依据的其他路径，不能通过同时开启几个开关绕过限制。

## 客户端插帧 {#frame-generation}

这项实验功能在客户端生成额外显示帧，不会提高主机游戏实际模拟帧率，也不能消除网络或输入瓶颈。

### 准备设备与引擎

1. 在 **设置 → 解锁开发者功能** 按客户端提示完成验证。12.13.0 的该入口使用 GitHub 登录并检查项目 Star；基础串流不要求解锁。
2. 进入 **帧生成 → 检查设备支持**。该版要求 Android 10+、64 位 ARM 与 Vulkan 1.1 等条件；仍以检测结果和串流实测为准。
3. 从自己 Windows 电脑上已安装的 **Lossless Scaling** 中取得 `Lossless.dll` 并复制到手机，在 **导入插帧引擎文件** 中选择。先检查导入结果，不从不明来源获取 DLL。
4. 选择普通支持路径，关闭 PyroWave，先让真实串流帧率稳定；记录设备温度与解码／渲染耗时。

### 以 120 Hz 输出为例

1. 确认手机系统与屏幕已使用合适的刷新率，将串流请求设为 **60 FPS**，目标输出为 **120 Hz**。
2. 开启 **插帧增强**，从客户端推荐的性能优先配置开始，**下次串流**重新连接生效。
3. 对比开关前后的运动连贯性、边缘伪影、触控感受和设备温度。界面显示更高输出帧率，不等于主机游戏已运行在相同帧率。
4. 有余量再调整插帧画质或渲染比例；不要同时提高串流分辨率和所有质量参数。

“自定义渲染比例”作用于客户端插帧处理，与[主机渲染分辨率比例](./settings.md#render-resolution)不同。黑屏、伪影或发热明显时关闭插帧并重连，必要时回到推荐质量与原串流帧率。

## 弱网补帧 {#adaptive-frame-generation}

**弱网补帧**针对丢帧或接收帧率不稳，尝试把显示补偿到接近目标帧率；它不要求固定使用 60 FPS，也不能补回丢失的输入和网络数据。

先用[ABR／FEC 和网络排查](./settings.md#自动码率与丢包保护-fec)改善链路，再单独试这一项。若画面看起来更顺但操作仍延迟，仍需处理传输瓶颈。关闭后重连验证普通路径，记录效果后决定是否保留。

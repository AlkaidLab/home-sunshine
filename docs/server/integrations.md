# AI 与可选集成

下面的工具不影响基础串流，可以按需要单独配置。桌面 GUI、Sunshine 管理 WebUI 和浏览器串流客户端是不同入口，请按使用目的选择对应入口。

## AI 日志诊断与配置辅助 {#ai-diagnosis}

需要自己的兼容模型服务。桌面 GUI 提供 **AI 助手／米塔 AI 助手**，首次先完成模型配置，再调用日志诊断。

1. 打开助手的 **模型配置**，选择实际使用的供应商，填写对应 API 地址、密钥和模型名称。
2. 使用 **测试连接**，成功后保存并按需要启用。模型列表获取失败时，先核对服务地址及可用模型，不修改 Sunshine 的串流参数排查 API 连接。
3. 先按[日志收集](../troubleshooting/logs.md)定位一次失败的时间范围，再使用日志诊断入口，说明主机、客户端、复现步骤和错误时间。
4. 对照原始日志核对分析结果。涉及命令、驱动、显示器和应用配置的建议，先检查它实际要改的内容，再逐项验证。
5. 不再使用时关闭助手；需要撤销授权时清除保存的 API 密钥，并按模型服务提供方的方式处理相应密钥。

日志及请求会交给所配置的模型服务，提交前检查主机地址、身份与私人内容。AI 的诊断、命令生成和封面整理是辅助能力，不代表建议已经在你的电脑上测试成功。没有模型服务时，仍可使用普通日志与[故障排查](../troubleshooting/index.md)。

## 使用 Moonlight Web 网页串流 {#web-client}

这是桌面 GUI 管理的第三方网页客户端组件，**`https://localhost:47990` 管理 WebUI 本身不会显示远程桌面**。

1. 先用原生 Moonlight 完成一次 Desktop 连接，确认 Sunshine 画面、声音和输入正常。
2. 打开桌面 GUI 的 **Web 串流**，查看组件状态；未安装时从该入口下载安装匹配的 Moonlight Web 组件。
3. 检查 **服务配置**中的绑定地址、HTTPS、默认编码和帧率。首次保留适合本机／受控局域网的范围，先用 H.264 与基础画质。
4. 保存并启动服务；服务运行时修改配置，需要按提示重启。使用界面生成的 **访问链接**，按网页客户端自身的账号、主机添加与配对流程操作。
5. 验证浏览器内的画面、声音、键鼠／手柄及退出行为。网页端不自动继承原生 V+ 的全部扩展。

HTTPS、自签名证书、浏览器权限和网络访问还需与该网页服务的文档匹配。自签名证书提示应针对自己确认的地址处理；不要全局关闭证书检查，也不要把 Sunshine 管理入口当作网页串流服务向外发布。

回退时停止 Web 串流服务，继续用已验证的原生客户端；无需为停用网页组件删除 Sunshine 配对与应用配置。

## 局域网二维码配对 {#qr-pairing}

二维码配对为**实验性功能，仅限局域网**，需要客户端提供扫码配对入口。请在客户端内扫描；没有该入口时，使用 [PIN 配对](../getting-started/index.md#_4-添加主机并输入-pin)。

1. 让主机与扫码客户端位于可互访的局域网，在 Sunshine **PIN 码** 页打开 **二维码配对 → 生成二维码**。
2. 使用目标客户端自己的配对扫描入口扫描，观察过期时间；过期后在主机刷新二维码。
3. 在主机与客户端确认配对成功，再连接 Desktop 检查画面与输入。
4. 扫码失败、客户端不支持或不在局域网时，回到手动 PIN；不需要更改主机服务模式。

配对材料只用于自己控制的设备，不公开二维码或用作教程示例。误配时在主机配对列表撤销该设备，再验证它不再获准连接。

# 卡顿、丢帧与高延迟

先用一个能稳定运行的场景作对照，再看瓶颈在哪一段。游戏在主机本地已经掉帧时，串流不会自动让它流畅。

## 1. 恢复对照配置

断开连接，将客户端设为 **1080p / 60 FPS、10 Mbps、SDR、自动或 H.264、立体声 / Opus**，关闭额外画面处理。主机优先接网线，无线客户端靠近路由器。

先连接 Desktop 拖动窗口或播放视频，再进游戏。静态桌面 FPS 较低可能只是没有新画面，应在持续运动时判断。

## 2. 打开性能统计

<ManualDiagram kind="latency" />

同时查看客户端性能浮窗和 Sunshine 的运行状态／日志。按观察结果选择下一步：

| 现象 | 优先检查 | 对照操作 |
| --- | --- | --- |
| 网络丢帧、延迟或抖动上升 | Wi-Fi、拥塞、跨网路径 | 降码率，暂停上传下载，改有线或靠近路由器 |
| 主机处理耗时高、输出 FPS 不足 | 游戏负载、捕获、编码、额外增强 | 降游戏画质，关增强，确认硬件编码，再对比 |
| 网络正常，客户端解码耗时高 | 格式、硬件解码、发热降频 | 改 H.264／HEVC，降分辨率，对比冷机与持续运行 |
| FPS 正常但周期性顿一下 | 刷新率、游戏稳定性、帧队列 | 先固定 60 FPS，对比默认同步／帧节奏设置 |
| 指标正常，电视仍感觉延迟高 | 电视画面处理、外设路径 | 比较游戏模式，分别验证本机显示和输入 |

这些是定位方向，不是单凭某个字段就能确定的结论。不同客户端的统计定义不同，见[性能指标说明](../clients/settings.md#打开性能统计)。

## 3. 只改变一个变量

从稳定配置先提高码率，再提高分辨率或帧率，每次使用同一场景观察。确认普通串流正常后，再启用 HDR、4:4:4、帧生成或其他增强。

60 FPS 的帧间隔约 16.7 ms，120 FPS 约 8.3 ms。处理持续跟不上目标时，先降低负载或目标帧率；不要直接把所有队列都调到最小来掩盖瓶颈。

## 4. 外网单独检查

局域网流畅、外网卡顿时，检查主机上传带宽、客户端网络和组网是否经过中继。主机家宽下载很快，不代表上传或跨运营商路径足够稳定。

查看组网工具的实际连接路径。先降低码率，再判断是否需要调整组网或网络条件；高码率和自适应码率都不能解决主机根本不可达的问题。

## 5. 保留可对比结果

记录同一场景下“修改前／修改后”的参数、性能统计和时间。若仍复现，按[日志反馈指南](./logs.md)提供两端版本、显卡、客户端设备及网络路径。

# 声音、麦克风与手柄

先分别确认播放、录音和基础输入正常，再启用多声道、麦克风回传或高级手柄反馈。

## 把主机声音传到客户端

1. 在主机播放一段音频，确认 Windows 本机音频正常。
2. 在 Sunshine 音频设置中选择实际需要捕获的输出设备。
3. 客户端先选择**立体声 / Opus**，断开后重新连接验证。
4. 检查客户端系统音量、耳机输出和应用是否静音。

主机本地扬声器是否继续播放，还受客户端请求影响。Android V+ 的“同时在主机播放声音”控制是否让主机与客户端同时输出；其他客户端按对应选项设置，并核对服务端的捕获和输出设备。客户端自身静音是另一项设置；把设备当副屏且不需要声音时，可在客户端关闭串流音频。

需要多声道或 PCM、AC3、E-AC3 等格式时，按实际客户端、扬声器和功放能力逐项尝试。能选择某个格式，不代表整个链路都能解码或直通。

## 把客户端麦克风传回主机

1. 在服务端桌面 GUI 的设备中心检查麦克风组件和虚拟录音设备，按需要安装。
2. 在支持回传的客户端开启麦克风功能，授予系统录音权限，检查进入串流时的初始静音状态。
3. 连接后在主机的 Windows 声音输入设置或录音应用中选择对应设备，说话观察输入电平。
4. 在游戏或语音软件中选择同一个输入设备，再做实际通话测试。

按钮存在但没有电平时，检查主机是否提供了麦克风通道、客户端权限和双方版本；不要只反复更换 Windows 默认设备。普通上游客户端不一定支持基地版的麦克风扩展。

## 基础手柄输入

1. 先在客户端设备本机连接实体手柄，确认系统能识别按钮与摇杆。
2. 在 Sunshine 设备中心检查当前虚拟手柄组件；按目标游戏需求选择 Xbox 360、DualShock 4 或当前版本提供的其他类型。
3. 重新建立连接，用主机的控制器测试入口或游戏检查输入。

改变类型通常影响之后新建的虚拟手柄。先断开重连再判断，不要同时让多个输入映射工具重复模拟同一只手柄。

## DualSense 与触觉

当前提供 DualSense 的版本可在 **设备中心 → 控制器** 安装相关组件，再选择全局或单游戏的虚拟手柄类型。先确认普通按键，再用支持该功能的游戏测试自适应扳机、音频触觉等反馈。

区分三类效果：

| 效果 | 来源与条件 |
| --- | --- |
| 普通游戏振动 | 游戏的 Rumble 指令，需要两端与手柄支持 |
| 音频模拟振动 | 客户端从声音生成振动，并不等于游戏原生触觉 |
| DualSense 高级反馈 | 游戏、虚拟设备组件、客户端及实体连接路径共同支持 |

高级触觉可能需要额外传输组件。USB、蓝牙及不同系统的能力不同，不能仅凭手柄型号保证所有效果可用。不要因旧教程出现 ViGEmBus 字样，就为所有手柄问题安装同一份历史驱动。

按[手柄、DualSense 与高级触觉](../clients/controllers.md)配置组件、测试普通输入与 HD Haptics，并确认共享 USB 驱动的依赖。麦克风后端、USB 转发和手柄触觉可能共用传输组件，停用一项功能时先关闭对应配置，不直接卸载所有驱动。

无声、回声、无输入或自动滚动见[音频与输入排查](../troubleshooting/audio-input.md)。

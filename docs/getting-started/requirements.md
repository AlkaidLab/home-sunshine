# 开始前的准备

串流需要主机能采集和编码画面、客户端能解码，以及网络能及时送达数据。先确认这三段都能工作，比直接照抄别人的高画质参数更有效。

## 主机：运行游戏的电脑

| 项目 | 起点与检查方法 |
| --- | --- |
| 系统 | 本手册面向 Windows。官网及当前虚拟显示器发行说明要求 Windows 10 22H2 或更高版本 |
| 显卡 | 优先使用支持硬件编码的 NVIDIA、AMD 或 Intel GPU；能玩游戏不等于支持每一种视频编码 |
| 驱动 | 使用适合该显卡、经项目发行说明确认兼容的驱动；遇到问题记录完整版本号 |
| 显示器 | 有一块可采集的物理屏，或已正确安装并启用基地虚拟显示器 |
| 运行状态 | Windows 已进入可用桌面，主机不会在测试途中自动睡眠 |

硬件编码的具体格式取决于显卡型号。第一次连接使用自动或 H.264；HEVC、AV1、10-bit、4:4:4 和高帧率需要分别检查两端能力。不要用软件编码的结果推断硬件编码的性能。

笔记本可能同时有核显和独显。先确认**目标显示器由哪块 GPU 驱动**，再选择捕获与编码路径；不要把“必须开启独显直连”当成所有机器的安装前提。

## 客户端：手边的设备

安装与你的系统和处理器架构匹配的客户端。macOS 的 Apple Silicon 和 Intel 包、Linux 的 x86_64 和 aarch64 包不能随意互换，详见[桌面客户端](../clients/desktop.md)。

客户端屏幕刷新率决定你实际能看到的刷新节奏。60 Hz 屏先用 60 FPS；开启 120 FPS 还需要屏幕、解码器、网络和主机共同跟得上。

连接手柄、耳机或外接屏后，先在客户端设备本机确认它们正常，再进入串流。

## 网络：先建立局域网基线

- 主机优先接网线；客户端无线连接优先用条件合适的 5 GHz 或 6 GHz Wi-Fi。
- 两端接同一个可互访的网络。访客 Wi-Fi、AP 隔离和公司网络策略可能阻断设备互通。
- 测试时暂停大流量下载、云备份和上传。路由器标称速率不等于当前链路的可用带宽或稳定性。
- 先走普通局域网路径；完成后再单独测试 VPN、组网或公网连接。

两端不一定需要处于同一个 Wi-Fi 频段，但必须有可通的路由。手机在移动数据网络时，不会因为和电脑登录了同一个客户端账号就自动处于同一局域网。

## HDR 和虚拟屏是下一步

普通 SDR 串流不要求 HDR 屏。HDR 需要主机输出、视频编码、客户端解码和终端显示全部支持；虚拟显示器只解决主机屏幕来源，不能给客户端屏幕增加 HDR 能力。

无物理屏、希望熄灭本地屏幕或使用不同长宽比时，再按[显示器指南](../server/display.md)配置虚拟屏。保留一个能恢复主机显示的本地操作入口，再测试仅启用虚拟屏的策略。

准备完成后，继续[第一次串流](./index.md)。
